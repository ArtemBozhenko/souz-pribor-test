# Ресерч 01. SEO и контент карточки товара КИП

Зона: контентные и SEO-блоки выхода сервиса (title, SEO-описание, характеристики, поисковые запросы, commercial-блок).
Дата: 2026-11-02. Все утверждения со ссылками; номера в квадратных скобках ведут к списку источников в конце.

## 0. Сначала о примере из ТЗ

В ТЗ стоит пример `"Манометр показывающий DM 02"`, производитель `"Манотомь"`. В реальности это две разные компании:

- **ДМ 02** — модель ООО «МЕТЕР» (Санкт-Петербург): Госреестр СИ № 25264-08, «Метер ДМ, исп. ДМ 01, ДМ 02, …», ТУ 4212-001-15151288-2007 [30]. Все магазины продают ДМ 02 как «МЕТЕР» [21][22][23][24][25].
- **ОАО «Манотомь»** (Томск) делает 100-миллиметровые технические манометры под другими названиями: МП3-У, а также МП4-У (160 мм), ДМ2005Сг, ДМ2010Сг [26][27].
- Модель пишут кириллицей и в разных вариантах: «ДМ 02», «ДМ02», «ДМ 02-100», «ДМ02-100-1-G» [21][22][24][25]. В ТЗ она записана латиницей, «DM 02».

**Вывод для промпта.** Внешними знаниями модель вход не исправляет: бренд и название берутся только из входных данных, по требованию ТЗ «не выдумывать». Подозрение на несоответствие можно вынести в отдельное поле `warnings`/«требует проверки», например «модель ДМ 02 обычно относится к другому производителю — проверьте». В сами тексты карточки такое подозрение не попадает. Для поисковых запросов полезно учесть варианты написания модели: «дм 02», «дм02», «DM 02». Это не техническая характеристика, а орфография запроса, поэтому фактов здесь модель не выдумывает.

## 1. SEO-заголовок (title) до 70 символов

### 1.1. Что говорят поисковики

**Google, Search Central «Influencing your title links»** [1]:
- Явного лимита нет: «there's no limit on how long a `<title>` element can be», но длинный title обрезается под ширину экрана. Нужен «descriptive and concise text».
- Ключевые слова не повторять: «there's no reason to have the same words or phrases appear multiple times». Повторы выглядят как спам.
- Шаблонный текст (boilerplate) вредит. Если title разных страниц отличается одной деталью, общая часть считается неинформативной.
- Бренд сайта ставится в начало или в конец через разделитель (дефис, двоеточие, вертикальная черта). Слоган на каждой странице не нужен.
- Title link Google собирает автоматически из `<title>`, H1, og:title и анкоров. Если title не соответствует странице, Google его перепишет. Значит, title должен совпадать по смыслу с H1.

**Яндекс, «Как правильно написать title»** [3]:
- Заголовок должен быть информативным, без общих формулировок.
- Не делать его слишком длинным, иначе он будет укорочен.
- Не перегружать ключевыми словами: «Используйте его для нескольких информационно важных фраз, не повторяйте их несколько раз… поиск может посчитать такой заголовок спамом».
- **Шаблон хвоста прямо назван плохим:** «не используйте заголовки с изменениями отдельных фраз: „<Название товара> — описание, цены, характеристики, фото, отзывы“. Такой заголовок малоинформативен.» Слова «фото» и «отзывы» стоит подставлять, только если такой контент на странице есть.
- Бренд добавлять в начале или в конце через двоеточие, дефис или вертикальную черту.
- Источники заголовка сниппета: `title`, контент страницы с учётом Schema.org, Яндекс Маркет, анкоры [2].

**Google Merchant Center, атрибут `title`** (не SEO title, но хорошая формула для товара) [8]:
- Лимит 150 символов, но «Users will usually notice only the first 70 or fewer characters». Самое важное ставится в начало.
- Включать название продукта, бренд (если он отличает товар) и отличительные атрибуты варианта (размер, цвет и т. п.).
- Без цены, скидок, сроков доставки, CAPS, символов и HTML.

### 1.2. Формула title для карточки КИП

Сведено из [1][3][8] и практики магазинов (раздел 1.3):

```
[Тип прибора] [Модель] [Производитель] [ключевой параметр 1: диапазон] [параметр 2: присоединение] [параметр 3: диаметр/класс]
```

Порядок важности параметров для показывающего манометра: тип → модель → бренд производителя → диапазон → резьба → диаметр → класс точности. Именно эти поля магазины выносят в название варианта [21][22][24][25]. Для датчиков давления вместо диаметра идут выходной сигнал и погрешность, например «4…20 мА, 0,5 %» [28].

Ограничение в 70 символов взято из ТЗ. Оно примерно совпадает с видимой частью у Google Merchant [8], а Google и Яндекс жёстких лимитов не задают [1][3].

Примеры для входа из ТЗ (длина посчитана скриптом):

| Вариант | Символов |
|---|---|
| `Манометр показывающий DM 02 Манотомь 0–1,6 МПа, кл. 1,5, G1/2, Ø100 мм` | 70 |
| `Манометр DM 02 Манотомь 0–1,6 МПа, G1/2, 100 мм — купить` | 56 |
| `Манометр DM 02 0–1,6 МПа, G1/2, 100 мм, кл. 1,5 \| Манотомь` | 58 |

### 1.4. Что применяем в промпте и выходе

1. `seo_title` не длиннее 70 символов. **Длину проверяет код** (`len()`); если превышено, генерация повторяется или параметры отбрасываются с конца. Модели плохо считают символы, поэтому проверка в коде обязательна.
2. Формула: `{тип} {модель} {производитель} {диапазон}, {присоединение}, {диаметр|выход}` с удалением параметров справа налево, пока не уложимся в лимит. В title попадают только значения из входа. Если параметра нет, он просто не включается, «данных нет» в title не пишется.
3. Каждое слово встречается один раз. Без слов «описание, цены, характеристики, фото, отзывы» [3], без цены, наличия, CAPS и «!» [8].
4. Название сайта не добавлять: на souz-pribor.ru CMS сама ставит суффикс « купить в СОЮЗ-ПРИБОР» [17][18][19]. Это стоит отметить в README и, возможно, сделать флаг `--title-suffix` или бюджет «70 минус суффикс».
5. Модель пишется так, как во входе. Диапазон оформляется через короткое тире или многоточие: «0–1,6 МПа» или «0…1,6 МПа», между числом и единицей пробел (ГОСТ 8.417 [33]).

## 2. SEO-описание 800–1200 символов

### 2.1. Что это по сути: текст на странице, а не meta description

- **Meta description** — тег `<meta name="description">`. В Google сниппет «primarily created from the page content itself», а meta description используется, только если точнее описывает страницу. Явного лимита нет, сниппет обрезается под ширину экрана [4]. У Яндекса похоже: description — один из источников сниппета, длина ограничена шириной экрана, важное нужно ставить в начало, description должен отличаться от title [2][5].
- 800–1200 символов во много раз длиннее того, что поместится в сниппет. Значит, «SEO-описание» из ТЗ — это **описательный текст на странице товара** (блок «Описание» на souz-pribor.ru [17][18]). Его же CMS может обрезать для `Product.description` в JSON-LD: на souz-pribor.ru описание там обрезано многоточием [17].
- Google Merchant: `description` до 5000 символов, главное в первых ~160–500 символах [9].
- **Вывод:** генерируем on-page текст на 800–1200 символов. Отдельный `meta_description` (~150–160 символов, первые 1–2 предложения выжимки) — дешёвое улучшение, его стоит описать в «возможных улучшениях» или отдать бонусным полем. Цифра «~160» — отраслевая условность, официальных лимитов у Google и Яндекса нет [4][5].

### 2.2. Требования поисковиков к качеству текста

**Google, Helpful content** [6]:
- «After reading your content, will someone leave feeling they've learned enough…»
- Без «easily-verified factual errors». Контент не должен быть «primarily made to attract visits from search engines».
- Про ИИ: «using generative AI to produce large amounts of text without manual oversight or curation represents little to no effort». Отсюда позиция сервиса: он делает **черновик для контент-менеджера**, а не публикует автоматически. Это стоит прямо написать в README.

**Яндекс, «SEO-тексты» и «Баден-Баден»** [11][12][13]:
- Нарушения: «Запросный спам», «Переоптимизация — в тексте избыточно используют слова… искусственно увеличивая объем контента, но не решая при этом задачу читателя», скрытый текст [11].
- Нарушением **не считаются** «уместные повторы… обусловленные спецификой ресурса» и стандарты и инструкции, где повтор терминов — норма [11]. Повторы «манометр» и «давление» в техописании допустимы, если они естественны.
- Баден-Баден (2017) понижает переоптимизированные страницы в ранжировании [12].
- Яндекс про тексты на коммерческих сайтах: «не имеет значения, какого объема текст и сколько в нем ключевых слов — главное, чтобы он был полезен для посетителей». Совет — спросить продавцов, какие вопросы клиенты задают о товаре: характеристики, отличия от других моделей, гарантия [13].
- Яндекс про оформление: «Основная суть документа должна быть понятна уже на первом экране» [14].

### 2.3. Структура продающего технического описания

Собрана из того, что повторяется у производителей и сильных магазинов:

1. **Назначение, первое предложение.** Что измеряет и в каких средах. Почти все пишут шаблоном из паспорта: «предназначен для измерения избыточного… давления неагрессивных… сред» [21][23][26]. Это нормально, но первое предложение должно включать модель и тип.
2. **Ключевые параметры словами.** Диапазон, класс, присоединение, диаметр, связанные с практическим смыслом. Хороший пример — manometer-spb.ru: «имеет радиальное присоединение (штуцер снизу), приборное стекло, класс точности 1,5…» и явное ограничение «Не подходит в работе с агрессивными, вязкими и кристаллизующимися рабочими средами» [21].
3. **Конструктивные особенности и преимущества.** ОВЕН выделяет «Отличительные особенности» списком с причиной: «Стойкость к агрессивным средам — сенсор вварен в штуцер лазерной сваркой» [28]. Endress+Hauser в блоке «Benefits» связывает свойство с выгодой: «High reference accuracy of 0.3%… ensures a high quality of process monitoring» [29].
4. **Области применения.** WIKA даёт их отдельным списком: «Hydraulic and pneumatic systems; Pumps, compressors, water systems» [31]. souz-pribor.ru пишет одну строку: «Область применения: теплоснабжение, водоснабжение…» [17][18].
5. **Ограничения и что уточнить при заказе.** souz-pribor.ru: «Шкала и варианты исполнения будут соответствовать параметрам, указанным при заказе» [17][18].

Плохие примеры:
- **Противоречия внутри карточки.** manometer-spb.ru: в тексте «Корпус выполнен из стали черного цвета», в таблице «Нержавеющая сталь 08Х18Н10» [21]. souz-pribor.ru, ТМ-520Р: в кратких характеристиках «IP65», в таблице «IP 54» [17]. chipdip у ДМ 02 указывает IP43, а у производителя IP40/IP54 [22a][20]. Это аргумент за правило «только из входа» и за проверку консистентности.
- **Обещания, которых нет в данных.** «Применяется во многих сферах промышленности, таких как нефтяная, газовая, химическая» [21] — общая фраза без опоры на паспорт.
- **Логистика вместо описания.** Длинные блоки про доставку и склады внутри описания товара [24][23]. Merchant Center тоже требует не включать доставку, историю компании и сравнения с другими товарами [9].

### 2.4. Что применяем в промпте и выходе

1. `seo_description` — 800–1200 символов с пробелами. **Длину проверяет код**; при выходе за границы — один повторный запрос с указанием фактической длины.
2. Структура из 3–4 абзацев: назначение (модель + тип + среда) → ключевые параметры словами → конструктив и практический смысл → применение и что уточнить при заказе.
3. Все числа и единицы берутся только из `specs`/`description` входа. Производных значений модель не вычисляет: например, абсолютную погрешность по классу точности. Это отдельный риск.
4. Если параметра нет, в описании он не упоминается. «Данных нет» пишется в таблице характеристик, а не в художественном тексте, иначе текст становится нечитаемым.
5. Запрещено: превосходные степени без опоры («лучший», «самый надёжный»), сравнение с другими брендами, цена, сроки, доставка, история компании [9]. Ключевое слово «манометр + модель» звучит 1–2 раза, без списков запросов [11].
6. Применение («для котельных, насосных станций») допускается, только если оно следует из входа или из типа среды во входе. Иначе применение идёт в commercial-блок с пометкой «типичные задачи для приборов этого класса, проверить», а не в публичный текст.
7. Опционально: `meta_description` до ~160 символов, отличный от title [5].

## 3. Структурированный список характеристик

### 3.1. Как подают топовые сайты

- **Таблица «Наименование — Значение» в одну колонку значений.** Так делают ОВЕН (`Наименование | Значение`, отдельная вкладка «Технические характеристики») [28], Манотомь [26], souz-pribor.ru [17][18], dn.ru [22].
- **Группы.** dn.ru делит на «Основные технические характеристики», «Подключение и установка», «Материалы», «Размеры» [22]. WIKA — «Applications / Product features / Specifications» [31]. Baymard: если характеристик больше ~20, их нужно группировать в подразделы с заголовками; 23 % сайтов этого не делают; ключевые параметры стоит поднять в краткую сводку [15].
- **Краткая сводка над полной таблицей.** souz-pribor.ru: «Краткие технические характеристики» списком плюс полная таблица [17]. chipdip показывает 4–5 параметров над ценой и «Все параметры» ниже [22a].
- **Единицы.** Либо в названии строки («Диаметр корпуса, мм | 100» [21]), либо в значении («100 мм» [17]). ГОСТ 8.417 допускает единицы в заголовках граф и строк таблиц и требует пробел между числом и единицей: «100 кВт», «80 %», «20 °C» [33]. ГОСТ 8.417-2002 заменён на ГОСТ 8.417-2024 с 30.09.2024 [33].
- **Значения «по заказу».** Манотомь и souz-pribor пишут «IP42 (по заказу IP53, IP54)», «1.5; 1.0 — по заказу» [26][18]. Это важно: базовое исполнение и опции различаются.

### 3.2. Разметка schema.org и фиды

- `Product.additionalProperty` → `PropertyValue` — «A property-value pair representing an additional characteristic of the entity», для характеристик без отдельного свойства в schema.org [16].
- У `PropertyValue` есть `name`, `value`, `unitCode` (UN/CEFACT, 3 символа), `unitText`, `minValue`/`maxValue` (для диапазонов вроде 0–1,6 МПа), `propertyID` [16a].
- **souz-pribor.ru уже использует** JSON-LD `Product` + `Brand` + `AggregateOffer` + `additionalProperty: PropertyValue{name, value}`, например `{"name":"Диаметр корпуса","value":"100 мм"}`, `{"name":"Класс точности","value":"1,0"}`. Выводится 4–7 свойств, без `unitCode` и без `minValue`/`maxValue` [17]. Наш формат характеристик стоит делать таким, чтобы он **напрямую ложился в эту разметку**: `name`, `value`, `unit`.
- Google Product snippet: обязательны `name` и одно из `offers`, `review`, `aggregateRating`. Про `additionalProperty` в требованиях Google ничего нет, это просто валидная разметка schema.org [7]. Яндекс учитывает Schema.org при формировании сниппета [2].
- Google Merchant `product_detail`: `section_name:attribute_name:attribute_value`, каждое поле 1–150 символов, до 100 штук. Правила: «Submit an attribute only when its value is confirmed», без ключевых слов, цены, доставки и названий компаний, регистр как в предложении [10]. Это хорошо совпадает с требованием ТЗ «не выдумывать» и с полем `group` в нашей схеме.

### 3.3. Что применяем в промпте и выходе

1. Схема элемента: `{ "group": "Измерение|Присоединение|Конструкция|Условия эксплуатации|Метрология", "name": "Диапазон измерений", "value": "0–1,6", "unit": "МПа", "source": "input|missing" }`.
2. Обязательный список полей для типа прибора (чек-лист). Для показывающего манометра: диапазон измерений, единица шкалы, класс точности, присоединение (резьба), расположение штуцера, диаметр корпуса, измеряемая среда, температура измеряемой среды, температура окружающей среды, степень защиты IP, межповерочный интервал, Госреестр СИ. Если поля нет во входе: `value: "данных нет"`, `source: "missing"`. Это одновременно реализует «сообщает, какие поля отсутствуют» из ТЗ.
3. Значения и единицы копируются из входа без пересчёта (МПа не переводятся в кгс/см²). Нормализуется только оформление: пробел перед единицей, десятичная запятая [33].
4. Названия характеристик даются в предложном регистре, без ключевых слов [10]. Сверху ставятся 4–6 ключевых полей, как в «краткой сводке» [15][17].
5. Отдельной функцией из этой структуры собирается JSON-LD `additionalProperty`, по образцу souz-pribor.ru [17]. Это бонус, его можно указать в улучшениях.

## 4. 3–5 поисковых запросов

### 4.1. Подход

- **Wordstat.** Операторы `!` (форма слова), `+` (стоп-слова), `" "` (точное число слов), `[]` (порядок), `()`/`|` (группы) [34][35]. Для семантики карточки смотрят точную частотность `"!фраза"` [36]. Wordstat требует авторизации, и в этом ресерче частоты **не замерялись**. Сервис должен честно называть запросы «кандидатами для проверки в Wordstat», а не «высокочастотными».
- **Интент.** Запросы делят на коммерческие («купить», «цена», «заказать»), которые ведут на карточки, и информационные («что такое», «как»), которые ведут на блог [36]. Для карточки нужны коммерческие и «модельные» запросы.
- **Структура спроса на КИП** видна из title магазинов (раздел 1.3): модель + бренд («ДМ02-100 МЕТЕР»), модель + параметр («0-10кгс/см2», «G1/2», «100 мм»), тип + назначение («манометр для котельной», «датчик давления для насосной станции» — так строит title ОВЕН [28]), тип + параметр («манометр G1/2», а у souz-pribor.ru есть посадочная фильтра «Манометры показывающие — G1/2» [20]).

### 4.2. Набор из 3–5 запросов (шаблон)

| Слот | Шаблон | Пример для входа ТЗ |
|---|---|---|
| Модельный НЧ, самый конверсионный | `{тип} {модель} {бренд}` | `манометр дм 02 манотомь` |
| Модель + коммерческий модификатор | `{модель} купить` / `{тип} {модель} цена` | `манометр дм02 купить` |
| Модель + ключевой параметр | `{тип} {модель} {диапазон\|диаметр}` | `манометр дм 02 100 мм` / `дм 02 1,6 мпа` |
| Тип + параметр (СЧ, категорийный) | `{тип} {присоединение} {диапазон}` | `манометр показывающий 1,6 мпа g1/2` |
| Тип + задача (только если среда или применение есть во входе) | `{тип} для {применение}` | `манометр для воды 1,6 мпа` (при условии, что вода есть во входе) |

### 4.3. Что применяем в промпте и выходе

1. 3–5 запросов в нижнем регистре, как их вводят люди; модель в разговорном написании (кириллица, с пробелом и без).
2. Минимум один запрос содержит модель, минимум один — коммерческий модификатор («купить» или «цена»), минимум один — числовой параметр из входа.
3. Без параметров, которых нет во входе, и без названий конкурентов.
4. Без городов, если их нет во входе: магазин работает на всю РФ [17].
5. Без дублей по смыслу (одинаковые словоформы).
6. В выходе пометка: «частотность не проверялась, сверить в Wordstat (`"!запрос"`)» [34][36]. Тип каждого запроса — `model | commercial | parameter | category | application` — для удобства контент-менеджера.

## 5. Commercial-блок для менеджера

### 5.1. Зачем и в каком формате

- Gartner: в B2B-закупке участвуют 6–10 человек, на встречи с поставщиками уходит лишь 17 % времени, а покупатель проходит «работы» Problem identification → Solution exploration → Requirements building → Supplier selection → Validation → Consensus creation [37][38]. Менеджеру нужна короткая шпаргалка: кому предложить, какую задачу прибор решает и какие вопросы задать, чтобы закрыть «Requirements building».
- **Battle card** в промышленности обычно включает: кому подходит, сценарии, вопросы для выявления потребности (discovery), возражения и ответы, «чего не говорить» [39][40]. Важное правило из шаблонов: каждое утверждение маркируется как факт или гипотеза, конкурентов не выдумывать [39][40]. Оно совпадает с требованием ТЗ.
- **Реальные примеры «кому подходит»** у производителей:
  - ОВЕН ПД100И: «предназначен для насосных станций, водоканалов, систем водоподготовки и водоснабжения, промышленных компрессорных, автоматики котлов в котельных» [28].
  - Endress+Hauser PMP21: «Field of application» + «Benefits» с формулой «свойство → выгода» (316L и IP68 → «Enhanced process availability»; сертификаты Ex и морские → «documentation and traceability») [29].
  - WIKA 111.10: «Hydraulic and pneumatic systems; Pumps, compressors, water systems, regulators; Suitable for fluid medium which does not clog connection port or corrode copper alloy» [31]. Здесь сразу и применение, и ограничение по среде.
  - souz-pribor.ru: «Область применения: теплоснабжение, водоснабжение, горнодобывающая промышленность, энергетика, машиностроение» [17]. В поле «Аналоги» — «ОБМ1-100; МОШ1-100; WIKA 111.10» [18]. Аналоги очень полезны менеджеру, но **из входа ТЗ их не вывести**, поэтому это кандидат на будущее улучшение с базой знаний.
  - ЭЛЕМЕР АИР-20/М2 перечисляет исполнения как сегменты: общепромышленное, Ex, атомное, кислородное, морское, нефтегазовое [32]. Так исполнение сразу показывает отрасль.

### 5.2. Что применяем в промпте и выходе

Структура `commercial` (для менеджера, не для публикации):

```json
{
  "target_customers": ["... (сегменты: ЖКХ/котельные, водоканалы, промпредприятия — только если следует из среды/назначения во входе)"],
  "tasks_solved": ["визуальный контроль давления в трубопроводе ...", "..."],
  "selling_points": [{"claim": "Класс точности 1,5", "benefit": "...", "basis": "input:specs.класс точности"}],
  "qualifying_questions": ["Какая измеряемая среда и её температура?", "Нужна ли поверка/какой межповерочный интервал?", "Какое присоединение на объекте — G1/2 или М20×1,5?", "Требуется ли виброустойчивость/гидрозаполнение?"],
  "limitations_or_check": ["Агрессивность среды к медным сплавам — данных нет, уточнить у клиента"],
  "basis_note": "Сегменты и задачи — типовые для класса прибора; технические значения — только из входных данных"
}
```

Правила:
1. Каждое преимущество в `selling_points` ссылается на поле входа через `basis`. Если ссылки нет, это не преимущество.
2. «Кому подходит» и «задачи» могут обобщать по классу прибора: показывающий манометр — визуальный контроль давления. Но они не вводят новых чисел и сертификатов (Ex, АЭС, кислород), если тех нет во входе. Такие обобщения помечаются как типовые.
3. Вопросы для выявления потребности строятся по полям со статусом `missing` из характеристик. Так отсутствующие данные превращаются в работу менеджера: «уточните среду», «уточните исполнение IP».
4. Без конкурентов, аналогов и цен (во входе их нет) [39][40].

## 6. Сводка правил для промпта (чек-лист)

1. Технические значения берутся только из входа. Пересчёта единиц и производных величин нет. Если поля нет — «данных нет» в характеристиках и отсутствие упоминания в текстах.
2. `seo_title` ≤ 70 символов (проверяет код). Формула «тип + модель + бренд + 1–3 параметра». Без «цены, фото, отзывы», без повторов, без названия магазина (суффикс ставит CMS) [1][3][8][17].
3. `seo_description` 800–1200 символов (проверяет код). On-page текст, а не meta. Абзацы: назначение → параметры → конструктив → применение и что уточнить. Без цены, доставки, сравнений и превосходных степеней [4][6][9][11].
4. `specs`: группы, порядок по важности, `name/value/unit/source`, совместимо с `additionalProperty`/`PropertyValue` и `product_detail` [10][15][16][17].
5. `search_queries` 3–5: модель / коммерческий / параметр / категория, нижний регистр, пометка «проверить в Wordstat» [34][36].
6. `commercial`: сегменты, задачи, преимущества с `basis`, вопросы по пропущенным полям, ограничения [28][29][37][39].
7. `warnings`: несостыковки во входе (например, модель и производитель, противоречивые значения). Модель их не исправляет, а только сигнализирует (см. раздел 0 и примеры противоречий в 2.3).
